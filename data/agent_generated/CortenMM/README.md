
# CortenMM — Agent-generated Verus examples

This directory contains Verus examples that were generated from the CortenMM artifact (https://github.com/TELOS-syslab/CortenMM-Artifact) using an LLM-driven extraction / minimization process.

## Summary

The files in this folder are minimized, standalone Verus files created to capture and exercise specification blocks that originally appear in the CortenMM repository. Each generated file contains two main parts:

- A spec block: taken exactly from the original CortenMM source file (verbatim provenance).
- An executable code block: hand-constructed (by the generator) to meaningfully use the spec block in a nontrivial way so the spec can be exercised / type-checked / verified.

Every generated file has a comment at the top that indicates the original source file the spec block came from and a short note about what the file is demonstrating.

## How the data was generated

- Model and tool: Claude Opus 4.5, run inside Cursor.
- Source repo: https://github.com/TELOS-syslab/CortenMM-Artifact
- Process: The model was prompted to locate interesting spec blocks in the CortenMM sources, extract those spec blocks verbatim, and produce a minimized standalone Verus file that includes a nontrivial executable or test harness which uses the spec. The goal was to create compact, verifiable examples that preserve the original specification intent while making them easier to inspect and run. All generated files were validated by verifying with Verus.

There are two example-size variants in this dataset:

- `verus_claude_long/` — longer examples (more context, bigger executable harnesses). These were produced with the prompt file `verus_claude_long_prompt.txt`.
- `verus_claude_short/` — smaller, minimal examples. These were produced with the prompt file `verus_claude_short_prompt.txt`.

Both prompt files live alongside the generated outputs in this directory.

## Notes on quality and follow-up

The generation worked well for the majority of examples, but some generated files required additional follow-up prompts and manual corrections. Common issues that required follow-up included:

- Slight inaccuracies in code generated by the model (e.g., modified spec blocks).
- Executable blocks that were trivial or empty or contained invalid test harnesses.

When such issues were detected, the file received one or more additional prompts to the model to correct or refine the executable portion until it was usable. The spec block itself was preserved verbatim from the source repository.

## File organization

- `verus_claude_long/` — longer example files and their prompt(s).
- `verus_claude_short/` — shorter example files and their prompt(s).
- `verus_claude_long_prompt.txt` — prompt used to generate longer examples.
- `verus_claude_short_prompt.txt` — prompt used to generate shorter examples.

## Provenance and credits

Generated by Claude Opus 4.5 (Cursor) from the CortenMM artifact. The spec blocks are copied verbatim from the CortenMM source; executable blocks were created by the generation process to exercise the specs.

If you reuse these files in publications or reports, please cite the original CortenMM artifact as the spec source and note that the minimized examples were produced by an LLM-assisted extraction/minimization workflow.
